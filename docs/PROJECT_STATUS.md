# SUPPLYSTAR 프로젝트 공식 상태

기준 시각: 2026-08-22 KST

## 현재 목표와 완료 조건

실제 온라인 결제 없이도 완성도 높은 쇼핑몰처럼 상품을 탐색할 수 있고, 상품 교체가 빠른 기업용 온라인 카탈로그를 만든다.

완료 조건은 상품 데이터의 단일 관리 위치, 실제 사진 교체 경로, 검색·분류·정렬·상세 보기, 문의목록, 오프라인 거래 안내, 모바일 대응, 자동 검증, Git 복구 지점이다.

## 확정된 결정과 이유

- 웹사이트에서 결제와 주문 확정은 제공하지 않는다. 실제 거래는 담당자 상담과 오프라인 계약·납품으로 진행한다.
- 쇼핑몰과 유사한 탐색 경험은 유지하되 `장바구니` 대신 `문의목록`으로 실제 거래 방식과 일치시킨다.
- 상품 정보는 `content/catalog.json` 한 파일에서 관리한다. 사용자가 직접 바꾸거나 자료를 전달해 Codex가 바꾸는 두 방식을 모두 지원하기 위해서다.
- 실제 상품 사진이 없을 때 AI로 가짜 상품 사진을 만들지 않는다. 브랜드 타이포 카드를 사용하고, 사진이 들어오면 경로 변경만으로 교체한다.
- 문의목록은 서버나 데이터베이스 없이 사용자 브라우저에만 저장한다.

## 완료한 작업

- 상품 15개와 카테고리 4개를 독립 카탈로그 데이터로 분리
- 상품 검색, 카테고리 필터, 추천·신상품·가격 정렬 구현
- 상품 상세 팝업과 브라우저 저장형 문의목록 구현
- 문의목록 텍스트 복사와 이메일 상담 연결 구현
- 오프라인 계약·납품 절차와 기업 서비스 안내 보강
- 데스크톱·태블릿·모바일 반응형 화면 개편
- 링크 공유용 전용 소셜 미리보기 이미지 추가
- 상품 교체 가이드와 카탈로그 자동 검사 추가
- 초기 스타터 기준 README와 테스트를 실제 프로젝트 기준으로 교체

## 미해결 문제

- 현재 `.openai/hosting.json`의 Sites 프로젝트 ID는 연결된 계정에서 `project not found`로 확인된다. 이 상태로는 Sites 새 버전을 저장하거나 배포할 수 없다.
- 실제 상품 사진은 아직 제공되지 않아 브랜드 타이포 카드가 표시된다.
- 기존 GitHub 원격 저장소에는 이번 변경을 푸시하지 않았다.
- 상품명, 가격, 규격, 회사 연락처는 기존 프로젝트 내용을 유지했으므로 실제 공개 전 사업 담당자의 최종 확인이 필요하다.

## 다음 단계

1. 실제 취급 상품 목록과 사진을 받아 `content/catalog.json`과 `public/products/`를 교체한다.
2. 상품명·가격·규격·사진과 회사 연락처를 사업 담당자가 확인한다.
3. 사용할 Sites 프로젝트 또는 새 배포 위치를 확정한다.
4. 배포 승인 후 검증된 커밋을 원격 저장소에 푸시하고 공개 버전을 생성한다.

## 중요한 제약과 주의사항

- 명시적 승인 없이 온라인 결제, 주문, 회원가입, 데이터베이스를 추가하지 않는다.
- 실제 상품과 다른 AI 생성 상품 이미지를 게시하지 않는다.
- 가격을 `null`로 두면 화면에 `견적 문의`로 표시된다.
- 상품 ID는 영문 소문자·숫자·하이픈만 사용하며 중복되면 안 된다.
- 공개 전에는 항상 `npm test`를 실행하고 실제 상품 정보와 이미지를 사람이 대조한다.
- 원격 푸시와 배포는 별도 승인 단계로 유지한다.
